# Contributing

Thanks for your interest in SBAppPortfolio. Issues and pull requests are welcome.

## How decisions are made

This project is maintained by [@slowbrewedmacchiato](https://github.com/slowbrewedmacchiato), who reviews and merges every pull request. That may change if maintainers are added later, but for now one person is the bottleneck, so please open an issue before starting substantial work. It avoids you building something that does not fit the direction of the package.

Small fixes, typos, and new locales do not need an issue first. Just open the PR.

## Getting set up

```bash
git clone https://github.com/slowbrewedmacchiato/SBAppPortfolio.git
cd SBAppPortfolio
swift build
swift test
```

The package has no external dependencies. `swift test` runs on macOS, which is why macOS appears alongside iOS in the platform list; iOS is the real deployment target.

To run the example app, open `Example/Thicket.xcodeproj`. It depends on the package by local path, so it always builds against your working copy.

## What CI checks

Every pull request runs three jobs, and all three must pass:

| Job | What it does |
| --- | --- |
| Package | `swift build` and `swift test` on macOS |
| Example app | Builds `Example/Thicket.xcodeproj` for the iOS Simulator |
| Localization | `Scripts/check-localization.py` |

You can run all three locally before pushing:

```bash
swift build && swift test
xcodebuild build -project Example/Thicket.xcodeproj -scheme Thicket \
  -destination 'generic/platform=iOS Simulator' CODE_SIGNING_ALLOWED=NO
python3 Scripts/check-localization.py
```

## Adding a locale

1. Add your language to `Sources/SBAppPortfolio/Resources/Localizable.xcstrings`, translating every key.
2. Add the same language to `Example/Thicket/Sources/Localization/Localizable.xcstrings` and to `knownRegions` in `Example/project.yml`.
3. Regenerate the example project: `cd Example && xcodegen generate`.
4. Update the locale list in the README's Localization section.
5. Run `python3 Scripts/check-localization.py`.

The localization check fails on a key missing from a catalog, on an empty translation, and on a key that covers only some of the catalog's locales. An empty string counts as untranslated, because it renders as English at runtime while looking complete in the editor.

## Style

- No en dashes or em dashes in code comments, documentation, or user-facing strings.
- User-facing strings go through `String(localized:comment:)` with a comment that explains where the string appears.
- Package strings must pass `bundle: .module`, or they resolve against the host app's bundle and fall back to English.
- Match the surrounding code. The package targets Swift 6 with strict concurrency.

## Changing the example app

`Example/Thicket.xcodeproj` is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `Example/project.yml` and committed so the example runs without installing XcodeGen. If you change `project.yml`, regenerate the project and commit both.
